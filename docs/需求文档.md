**情感陪伴自律 APP｜产品需求文档 v0.1（讨论稿）**

日期：2026 年 9 月 5 日。用途：确认产品方向及比赛首版范围，尚未确定产品名称、开发平台和技术方案。

**1. 产品定位与需求依据**

一句话定位：一个根据用户每天实际可用时间和状态，安排个人目标、陪伴执行并持续调整计划的 AI 自律助手。

首先服务下班时间不固定、希望在工作之外完成学习或个人项目的人。用户已经有想完成的目标，但回家后常常不知道从哪一步开始，或者原有安排被加班打乱。产品要帮助用户回答：“以我今天剩下的时间和精力，最值得做什么，做到什么程度就可以休息？”

用户已经明确的需求：情感类自律 APP；支持已有主计划和有截止日期的事项；由 Agent 每天规划任务并进行调度；适应不固定的下班时间；内置番茄钟和提醒。

本稿补充的设计建议：首批用户聚焦职场人；情感体验先采用温和教练式陪伴；手动报到作为每日规划入口；计划包含休息和缓冲；任务未完成时重新安排。以下具体规则及默认值均可在评审后修改。

**2. 核心使用流程**

建立主计划 → 补充目标及截止时间 → 确认可执行的子任务 → 每天回家后报到 → 告知今晚时间和状态 → Agent 生成今日安排 → 用户采纳或调整 → 开始番茄钟 → 反馈实际进度 → 重新安排剩余任务 → 简短复盘。

首次使用时，用户设置通常的可用时段、最晚结束时间、提醒偏好和番茄钟时长。通常时段只用于预估；当天实际输入优先。首次设置后，每天只需更新发生变化的信息。

**3. 主计划与任务管理（首版必做）**

用户可以手动建立主计划，也可以粘贴已有计划，由 Agent 提取目标和任务供用户修改。首版先支持文字输入及粘贴。

| 信息 | 需求 |
|---|---|
| 目标名称与完成标准 | 写清楚最终要得到什么，例如“完成作品集初稿，包含三个项目案例” |
| 截止时间 | 支持指定日期或暂不设置；只有日期时需明确默认结束时间和时区 |
| 优先级 | 用户可设置；多个目标冲突时用于取舍 |
| 子任务 | 每项包含名称、预计剩余时长、状态和完成标准 |
| 执行约束 | 支持前置任务、固定时段、不可拆分任务；普通任务默认允许分次完成 |
| 精力要求 | 可选择高、中、低，Agent 可以建议，用户可修改 |
| 可用时间 | 记录通常可用时段和当天例外，用于判断能否按期完成 |

Agent 将大目标拆成能够直接行动的步骤，例如“整理项目 A 的三张截图”，并给出时间估计。估计必须标明可调整，用户可以增加、删除、合并或修改任务。

用户已有清楚的子任务时，应优先保留。遇到模糊完成标准、日期歧义或缺少关键条件时，仅追问影响排程的信息。拆分结果经用户采纳后进入任务库。

任务状态至少包含：待开始、进行中、已完成、已取消。今日延后仅表示退出今日安排，任务仍保留，原截止时间不变。

**4. 每日状态与智能调度（首版必做）**

每日入口为“我到家了／开始安排今天”。用户确认：可以从几点开始、最晚几点结束、中间有哪些不能安排任务的时段；精力或心情可选填，也可直接说“今天很累，只想做半小时”。

心情和精力采用用户主动表达的信息。心情可以跳过；精力未填写时采用已保存偏好并允许修改。首版通过用户操作触发规划，无需自动判断用户位置或下班状态。

Agent 生成按时间排序的今日安排。每项显示开始和结束时间、具体行动、所属目标、预计时长，以及一句安排理由。首页清楚显示“下一步做什么”，并区分优先完成与时间充裕再做的内容。

调度遵守以下规则：

1. 先扣除固定事务、休息和缓冲，再安排任务；任务之间不能重叠，不能超出用户设定的结束时间。
2. 满足前置依赖和固定时段等约束后，综合截止时间、剩余工作量、优先级和精力要求决定顺序，避免只按截止日期机械排序。
3. 优先生成可以在当前时段推进的行动。允许拆分的任务可以分次进行；不可拆分且放不下的任务说明原因，安排到其他合适时段。
4. 同时参考截止日前的预计可用时间，判断今日投入是否足够。未来时间未知时显示“信息不足／按通常时段估算”，不承诺一定按期完成。
5. 若剩余工作量明显超过预计可用时间，明确显示差额，并提出减少范围、增加可用时间或修改截止时间的选项，交由用户选择。
6. 用户可以编辑、移除或锁定今日任务。首次生成的安排和重新安排的结果均可预览后采纳；锁定事项保留原位置。

用户可以说“刚接到电话，晚半小时开始”“这个任务比预计难”“我现在很累”“今天不做了”。Agent 据此更新剩余安排，并解释哪些任务移动、哪些保留、对目标进度有什么影响。

重排只处理尚未开始的时间块。已完成记录保持不变；正在计时的任务先由用户选择继续、暂停或结束。改动任务范围、截止时间、固定事务或最晚结束时间时，由用户明确选择。用户应能撤销刚采纳的重排。

当日没有可用时间时，可以直接形成休息安排，并提示下一次适合推进的任务。未完成任务进入后续排程重新评估，不把全部积压无条件塞进明天。

**5. 情感陪伴（首版必做，具体角色待确认）**

本稿暂按温和、理解疲惫、帮助开始行动的教练型伙伴设计。陪伴贯穿报到、开始专注、遇到中断和每日复盘四个节点。

| 场景 | 预期表现 |
|---|---|
| 用户疲惫 | 接纳用户状态，建议降低强度、缩短任务或休息，并说明进度影响 |
| 不知道如何开始 | 把眼前任务拆成一个容易开始的动作，例如“先选出三张截图” |
| 完成部分工作 | 结合真实记录反馈，例如“今晚已整理完项目 A 的截图” |
| 没有完成计划 | 引导调整剩余工作，不使用羞辱、内疚或连续打卡惩罚来催促 |

示例文案：“今天回来得晚，我们先把最重要的一小步完成。整理完这三张截图就可以停，剩余内容我会重新安排。”

陪伴反馈必须与实际任务和进度一致。专注过程中默认保持安静；用户可以关闭陪伴文案或主动发起对话。长期保留的偏好应可查看和修改，心情记录可删除。

**6. 番茄钟与提醒（首版必做）**

今日任务卡片提供“开始专注”按钮，自动关联当前任务。建议默认专注 25 分钟、短休息 5 分钟，每四轮可长休息 15 分钟；用户可自定义。计划剩余时间不足一轮时，提供短时专注或延后选项。

支持开始、暂停、继续、提前结束和切换任务。同一时间只允许一段专注计时。切换时结算上一段实际专注时长；暂停和休息不计入专注时间。

到时提醒用户选择“任务完成”“还需继续”或“今天先到这里”，然后进入休息或返回计划。番茄结束不自动代表任务完成，也不自动完成主目标。任务提前完成时，可手动结束并更新进度。

提醒覆盖三种事件：已采纳计划中的任务即将开始、专注结束、休息结束。声音、震动及系统通知依据所选平台能力提供；支持关闭和稍后提醒。提醒时段由用户设置，重排后旧提醒应取消，避免重复通知。

切后台、锁屏或重新打开应用后，应按真实经过时间恢复计时并避免重复记录。通知权限被拒绝时保留可见的计时和应用内提示。平台确定后，需要实际验收后台与锁屏提醒；若首版采用网页演示，必须标明关闭页面时通知的具体限制。

**7. 进度反馈与每日复盘（首版必做）**

每个任务记录实际专注时间、是否完成以及用户修正后的剩余时长。耗时记录可帮助 Agent 改进估计，但不能仅靠累计分钟数推断任务已经完成。

每日结束提供简短复盘：今天完成了什么、实际专注多久、剩下什么、目标是否有延期风险，以及下一次建议先做什么。用户可补充一句原因或心情，也可以跳过。

目标进度按已确认的任务或里程碑完成情况展示，并说明计算口径；需要同时展示尚未完成的关键事项，避免一个百分比掩盖实际进展。

**8. 页面与首版范围**

建议使用四个主要页面，番茄钟从任务卡进入：

| 页面 | 核心内容 |
|---|---|
| 今天 | 报到入口、当天状态、时间安排、下一步行动、开始专注、重新安排 |
| 计划 | 主目标、截止时间、子任务、优先级、剩余工作和延期风险 |
| 记录 | 专注记录、任务完成情况、每日复盘 |
| 我的 | 可用时段、结束时间、番茄设置、提醒和陪伴偏好、数据管理 |

首版必须跑通：录入一个主计划 → 拆分并采纳 → 根据当天状态生成安排 → 调整安排 → 番茄专注 → 反馈进度 → 根据剩余任务继续调度。多个目标并行时，也应能按优先级和期限做取舍。

建议后续再评估日历同步、语音交互、角色形象和更丰富的激励机制。是否开发原生手机 APP 或先做移动端网页，留待确认；后台提醒的要求会影响平台选择。

**9. 典型场景与演示脚本**

以下时间、目标和任务均为产品示例，不是比赛日期。

用户需要在两周内完成作品集，目前要整理项目 A 素材、撰写项目介绍并排版。今晚 21:00 到家，22:30 必须结束，精力一般，未来两周的通常可用时段已经设置。

| 时间 | 安排 | 目的 |
|---|---|---|
| 21:00—21:10 | 休息和准备 | 留出到家后的缓冲 |
| 21:10—21:35 | 整理项目 A 的截图 | 第一轮专注，完成后续写作的前置任务 |
| 21:35—21:40 | 休息 | 五分钟短休息 |
| 21:40—22:05 | 撰写项目 A 的介绍草稿 | 第二轮专注；前置素材需已完成 |
| 22:05—22:10 | 休息 | 五分钟短休息 |
| 22:10—22:20 | 检查缺失素材并反馈进度 | 较轻的收尾工作 |
| 22:20—22:30 | 机动时间 | 可用于延误或提前结束 |

这份安排合计 90 分钟：任务 60 分钟、休息及准备 20 分钟、机动 10 分钟。若第一项未完成，应重新评估后续写作，不直接假定前置条件满足。

演示中增加一次变化：“临时有事，21:30 才能开始。”Agent 将可用时间更新为 60 分钟，建议保留截图整理，推迟介绍写作，并提供新安排：准备 10 分钟、截图整理 25 分钟、休息 5 分钟、检查缺失素材 10 分钟、机动 10 分钟。随后检查剩余可用时间是否足以支持原截止时间，展示判断依据。

演示结束时，完成一轮短时演示计时，选择“还需继续”，展示实际时长已记录、任务仍未完成、剩余工作参与下次排程。若使用加速计时，界面标明演示模式。

**10. 首版验收标准**

| 编号 | 验收场景 | 通过条件 |
|---|---|---|
| A1 | 输入有截止时间的目标或粘贴主计划 | 生成可编辑子任务、完成标准和时间估计，经采纳后保存 |
| A2 | 输入今晚可用时段和精力 | 输出具体时间块及理由，含休息和缓冲，无重叠或越界 |
| A3 | 同时存在两个目标和任务依赖 | 排程遵守依赖和固定安排，并解释优先级取舍 |
| A4 | 晚开始半小时或临时插入事务 | 重新安排剩余任务，保留完成记录和锁定事项，展示差异供采纳 |
| A5 | 工作量超过截止日前预计容量 | 提示缺口及可选调整，不静默延期或强行排满 |
| A6 | 完成、暂停或提前结束番茄钟 | 正确累计实际专注时长，不把计时结束直接当成任务完成 |
| A7 | 切后台、锁屏后返回或拒绝通知权限 | 计时按真实时间恢复；符合平台声明的提醒能力，无重复记录 |
| A8 | 用户疲惫或当天零可用时间 | 允许降低强度或休息，保留目标并说明后续影响 |
| A9 | 网络中断或 Agent 生成失败 | 已保存计划、进度和本地计时仍可用；可重试或手动调整，失败结果不覆盖原计划 |
| A10 | 关闭并重新打开应用 | 已采纳计划、任务进度和偏好保留；用户能删除自己的记录 |

产品上线后可观察首次计划采纳率、从查看安排到开始专注的比例、任务完成情况和用户对安排合理性的反馈。本稿不预设未经验证的增长或完成率指标。

**12. 本轮优先确认的三个产品选择**

1. 情感体验：温和教练、虚拟伙伴，还是更有监督感的督促者？本稿默认温和教练。
2. 使用人群：先聚焦下班后安排个人目标的职场人，还是同时服务学生？本稿默认先聚焦职场人。
3. 首版形态：优先交付手机安装使用的 APP，还是先完成可演示的移动端网页？本稿暂不锁定平台。

主计划、每日调度和番茄钟属于用户已明确的核心；上述选择及默认规则将在下一版根据反馈调整。
